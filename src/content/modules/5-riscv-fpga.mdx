<div class="ieee-abstract">

## I. Microarchitecture & 5-Stage Datapath Overview

The RV32I datapath is segmented into five discrete stages separated by synchronous pipeline registers:

```text
[ IF ] ---> [ IF/ID ] ---> [ ID ] ---> [ ID/EX ] ---> [ EX ] ---> [ EX/MEM ] ---> [ MEM ] ---> [ MEM/WB ] ---> [ WB ]
  |                          |                           |                            |                           |
  +-- Instruction Memory     +-- 32-Entry RegFile        +-- 32-bit ALU               +-- Data Memory (BRAM)      +-- Writeback Multiplexer
```

1. **Instruction Fetch (IF):** Program Counter (PC) incremented by 4 or overwritten by branch target; accesses instruction ROM.
2. **Instruction Decode & Register Read (ID):** Immediate sign-extension, instruction field slicing, dual asynchronous register file read.
3. **Execution & Address Calculation (EX):** Arithmetic/Logical operations via the ALU; branch address evaluation.
4. **Memory Access (MEM):** Synchronous load/store access into internal FPGA Block RAM.
5. **Write Back (WB):** Selects between ALU output, Memory load data, or Return PC (`jal`/`jalr`) to write back into destination register $rd$.

## II. The Engineering Trap: Unresolved Read-After-Write (RAW) Load-Use Stall

<div class="glass-card p-5 rounded-2xl border border-red-500/40 bg-[#041026]/90 space-y-3 my-6">
  <div class="flex items-center gap-2 text-red-400 font-mono font-bold text-sm tracking-wide">
    <span class="text-base">⚠️</span>
    <span>ENGINEERING TRAP: UNRESOLVED LOAD-USE DATA HAZARD & TIMING PARADOX</span>
  </div>

  <p class="text-xs text-slate-200 leading-relaxed font-sans">
    While standard ALU-to-ALU forwarding resolves data dependencies between arithmetic instructions with zero stall cycles, an architectural timing paradox occurs when an instruction immediately consumes the result of a <code>lw</code> (Load Word) instruction.
  </p>

  <div class="p-3 rounded-xl bg-[#020813] border border-red-500/30 text-xs font-mono text-slate-300 space-y-2">
    <div class="text-amber-400 font-bold">1. The Critical Code Sequence:</div>
    <div class="bg-[#041026] p-2.5 rounded-lg border border-slate-800 text-slate-200">
      <code>lw   x1, 0(x2)    # Instruction 1: Loads memory content into x1 (available only at end of MEM stage)</code><br/>
      <code>add  x3, x1, x4   # Instruction 2: Demands x1 at beginning of EX stage!</code>
    </div>

    <div class="text-amber-400 font-bold pt-1">2. Temporal Impossibility:</div>
    <p>
      At Cycle 3, <code>lw</code> is in the <strong>EX</strong> stage (computing Effective Address $x2 + 0$), while <code>add</code> is in the <strong>ID</strong> stage. At Cycle 4, <code>lw</code> is in the <strong>MEM</strong> stage reading Block RAM, while <code>add</code> is in the <strong>EX</strong> stage requiring $x1$.<br/>
      Because the memory data is only valid at the <strong>end</strong> of the MEM cycle, <em>forwarding backwards in time is physically impossible!</em>
    </p>

    <div class="text-amber-400 font-bold pt-1">3. The Engineering Flaw:</div>
    <p>
      Inexperienced students frequently assume the forwarding unit can route <code>EX/MEM.ALU_out</code> to the ALU inputs. However, for a <code>lw</code>, <code>EX/MEM.ALU_out</code> holds the <em>memory address</em>, NOT the memory data! The ALU consequently executes <code>add</code> with the memory pointer instead of the actual data, causing silent numerical corruption in FIR filters and control loops.
    </p>
  </div>

  <div class="p-3 rounded-xl bg-[#00693E]/20 border border-[#00F0B5]/30 text-xs font-mono text-slate-300 space-y-1">
    <div class="text-[#00F0B5] font-bold">✓ RISC-V RTL Verification Solution:</div>
    <p>
      The <strong>Hazard Detection Unit</strong> must inspect the pipeline registers during the ID stage and force a 1-cycle bubble (NOP stall):
    </p>
    <div class="bg-[#020813] p-2 rounded border border-emerald-500/30 text-[#00F0B5]">
      <code>assign load_use_hazard = id_ex_mem_read &amp;&amp; ((id_ex_rd == if_id_rs1) || (id_ex_rd == if_id_rs2));</code>
    </div>
    <ul class="list-disc list-inside space-y-1 text-slate-300 pt-1">
      <li><strong>Freeze Program Counter:</strong> Inhibit <code>pc_en</code> so PC remains pointing to the subsequent instruction.</li>
      <li><strong>Freeze IF/ID Register:</strong> Inhibit <code>if_id_write</code> to re-decode the dependent instruction.</li>
      <li><strong>Inject Bubble:</strong> Clear all <code>id_ex_ctrl</code> signals to zero, executing a synchronous 1-cycle NOP in the pipeline.</li>
    </ul>
  </div>
</div>

## III. Verilog HDL Forwarding Unit & Hazard Detection RTL

The following synthesizable Verilog modules demonstrate the complete hazard resolution logic:

```verilog
// ============================================================================
// VoltCore Apex Academia - Module 5: Hazard Forwarding & Detection Unit
// Target: Xilinx Artix-7 FPGA (XC7A35T) | Language: Verilog HDL (IEEE 1364-2001)
// ============================================================================

module hazard_forwarding_unit (
    input  wire [4:0] id_ex_rs1,
    input  wire [4:0] id_ex_rs2,
    input  wire [4:0] ex_mem_rd,
    input  wire       ex_mem_reg_write,
    input  wire [4:0] mem_wb_rd,
    input  wire       mem_wb_reg_write,
    output reg  [1:0] forward_a,
    output reg  [1:0] forward_b
);

    // Forwarding logic for Operand A (ALU Input 1)
    always @(*) begin
        if (ex_mem_reg_write && (ex_mem_rd != 5'd0) && (ex_mem_rd == id_ex_rs1)) begin
            forward_a = 2'b10; // Forward from EX/MEM stage
        end else if (mem_wb_reg_write && (mem_wb_rd != 5'd0) && (mem_wb_rd == id_ex_rs1)) begin
            forward_a = 2'b01; // Forward from MEM/WB stage
        end else begin
            forward_a = 2'b00; // No forwarding, use register file value
        end
    end

    // Forwarding logic for Operand B (ALU Input 2)
    always @(*) begin
        if (ex_mem_reg_write && (ex_mem_rd != 5'd0) && (ex_mem_rd == id_ex_rs2)) begin
            forward_b = 2'b10; // Forward from EX/MEM stage
        end else if (mem_wb_reg_write && (mem_wb_rd != 5'd0) && (mem_wb_rd == id_ex_rs2)) begin
            forward_b = 2'b01; // Forward from MEM/WB stage
        end else begin
            forward_b = 2'b00; // No forwarding, use register file value
        end
    end

endmodule

// ============================================================================
// Load-Use Stall Detection Unit
// ============================================================================
module load_use_hazard_detector (
    input  wire [4:0] if_id_rs1,
    input  wire [4:0] if_id_rs2,
    input  wire [4:0] id_ex_rd,
    input  wire       id_ex_mem_read,
    output wire       stall_pipeline
);

    // Assert stall if instruction in EX is a load and destination matches ID source
    assign stall_pipeline = id_ex_mem_read && (id_ex_rd != 5'd0) &&
                           ((id_ex_rd == if_id_rs1) || (id_ex_rd == if_id_rs2));

endmodule
```
